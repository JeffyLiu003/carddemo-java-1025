# 11 Money Path Slice A2: Posting Engine and General Ledger

> Upstream: `10-money-path-slice-a1.md` (A1.2–A1.4)
> Status: in implementation
> Scope of this round: A1.2 posting engine (transaction-service), A1.3 general ledger (ledger-service), and the corresponding frontend pages

## 1. Goals

Connect one complete funds chain:

```
business request → posting batch (debit/credit journal lines) → account balance change
                              ↘ general ledger journal entry (double-entry) → trial balance → period close
```

At any moment: `Σ debit = Σ credit`; the same idempotency key produces only one batch; a reversal never deletes the original journal lines.

## 2. A1.2 Posting Engine (transaction-service)

### 2.1 Tables (V3 migration)

- `posting_type`: `type_code`, `name`, `description`, `account_effect` (INCREASE/DECREASE), `active`, `version`
- `posting_rule`: `rule_id`, `type_code`, `leg_no`, `account_role`, `direction` (DR/CR), `ledger_account_code`, `description`, `version`, unique `(type_code, leg_no)`
- `posting_batch`: `batch_id`, `idempotency_key` (unique), `type_code`, `account_id`, `amount`, `currency`, `description`, `status` (POSTED/REVERSED), `reversal_of`, `ledger_entry_id`, `created_at`, `reversed_at`, `version`
- `posting_leg`: `leg_id`, `batch_id`, `leg_no`, `account_role`, `direction`, `ledger_account_code`, `amount`, `created_at`, unique `(batch_id, leg_no)`

### 2.2 Seed Types and Rules

| typeCode | Name | Account effect | Journal lines |
|---|---|---|---|
| CARD_PURCHASE | Credit card purchase | INCREASE | DR 1100 / CR 2100 |
| CASH_ADVANCE | Cash advance | INCREASE | DR 1100 / CR 1000 |
| FEE | Fee | INCREASE | DR 1100 / CR 4000 |
| INTEREST | Interest | INCREASE | DR 1100 / CR 4100 |
| PAYMENT | Repayment | DECREASE | DR 1000 / CR 1100 |
| REFUND | Refund | DECREASE | DR 2100 / CR 1100 |
| ADJUSTMENT | Adjustment | INCREASE | DR 1100 / CR 9000 |

### 2.3 API

| Method | Path | Description |
|---|---|---|
| GET | `/api/v1/posting-types` | Type list (without rules) |
| GET | `/api/v1/posting-types/{typeCode}` | Type + rules |
| POST | `/api/v1/posting-batches` | Create a posting batch |
| GET | `/api/v1/posting-batches/{batchId}` | Batch details (including legs) |
| GET | `/api/v1/posting-batches?page=&size=&accountId=&idempotencyKey=` | Paged query |
| POST | `/api/v1/posting-batches/{batchId}/reversal` | Reverse, returns the reversal batch |

Create request:

```json
{"idempotencyKey":"post-20261026-0001","typeCode":"CARD_PURCHASE",
 "accountId":"00000000006","amount":25.00,"currency":"USD",
 "description":"Purchase at Corner Grocery"}
```

Response (201):

```json
{"batchId":"...","idempotencyKey":"...","typeCode":"CARD_PURCHASE","typeName":"Credit card purchase",
 "accountId":"00000000006","amount":25.00,"currency":"USD","description":"...",
 "status":"POSTED","reversalOf":null,"ledgerEntryId":"...","createdAt":"...","reversedAt":null,
 "legs":[{"legNo":1,"accountRole":"CARD_RECEIVABLE","direction":"DR",
          "ledgerAccountCode":"1100","amount":25.00},
         {"legNo":2,"accountRole":"MERCHANT_PAYABLE","direction":"CR",
          "ledgerAccountCode":"2100","amount":25.00}]}
```

Rules:

- The idempotency key is mandatory; a resubmission with the same `typeCode/accountId/amount` returns the original batch; otherwise 409 `IDEMPOTENCY_CONFLICT`.
- Unknown type 404 `POSTING_TYPE_NOT_FOUND`; inactive 409 `POSTING_TYPE_INACTIVE`.
- The amount must be > 0 (2 decimals), otherwise 409 `INVALID_POSTING_AMOUNT`.
- Unknown account 404 `ACCOUNT_NOT_FOUND`; account not `Y` 409 `ACCOUNT_INACTIVE`.
- The legs generated by the rules must balance and equal the batch amount, otherwise 409 `UNBALANCED_POSTING`.
- Account effect: INCREASE calls `POST /accounts/{id}/postings` with a positive number; DECREASE passes a negative number.
- The batch is saved only after the account call succeeds; a failed account call is propagated upward as 503.
- General ledger synchronization is best-effort: a failure only logs a WARN and does not affect the batch; on success `ledger_entry_id` is written.

Reversal:

- Original batch already REVERSED: return the existing reversal batch (looked up by `reversal_of`).
- The reversal batch has `idempotencyKey = "reversal:" + originalBatchId`, the legs have swapped directions, and the account is called in the opposite direction of the original effect.
- The original batch is marked REVERSED + `reversed_at`; the reversal batch `reversal_of` points to the original batch.
- Reversing a reversal batch is not allowed: 409 `REVERSAL_NOT_ALLOWED`.

### 2.4 General Ledger Client

`POST {LEDGER_SERVICE_URL}/api/v1/journal-entries`:

```json
{"sourceType":"POSTING_BATCH","sourceId":"<batchId>","description":"...",
 "postedAt":"2026-10-26T04:00:00","currency":"USD",
 "lines":[{"accountCode":"1100","direction":"DR","amount":25.00},
          {"accountCode":"2100","direction":"CR","amount":25.00}]}
```

Configuration: `LEDGER_SERVICE_URL` (default `http://localhost:8088`), `LEDGER_SYNC_ENABLED` (default true).

## 3. A1.3 General Ledger (ledger-service, :8088)

### 3.1 Tables

- `ledger_account`: `account_code`, `name`, `account_type` (ASSET/LIABILITY/EQUITY/REVENUE/EXPENSE), `parent_code`, `currency`, `active`, `version`
- `accounting_period`: `period` (YYYY-MM), `status` (OPEN/CLOSED), `closed_at`, `version`
- `journal_entry`: `entry_id`, `source_type`, `source_id`, `description`, `posted_at`, `status` (POSTED/REVERSED), `reversal_of`, `created_at`, `version`, unique `(source_type, source_id)`
- `journal_line`: `line_id`, `entry_id`, `line_no`, `account_code`, `direction` (DR/CR), `amount`, unique `(entry_id, line_no)`

### 3.3 API

| Method | Path | Description |
|---|---|---|
| GET | `/api/v1/ledger-accounts` | Chart of accounts |
| GET | `/api/v1/ledger-accounts/{code}` | Ledger account details |
| POST | `/api/v1/journal-entries` | Record a journal entry, idempotent on `(sourceType, sourceId)` |
| GET | `/api/v1/journal-entries/{entryId}` | Details |
| GET | `/api/v1/journal-entries?page=&size=&sourceId=` | Paged query |
| POST | `/api/v1/journal-entries/{entryId}/reversal` | Reverse |
| GET | `/api/v1/trial-balance?period=2026-10` | Trial balance |
| GET | `/api/v1/accounting-periods` | Period list |
| POST | `/api/v1/accounting-periods/{period}/close` | Close the period |

Journal entry request:

```json
{"sourceType":"POSTING_BATCH","sourceId":"b-1","description":"Card purchase",
 "postedAt":"2026-10-26T04:00:00","currency":"USD",
 "lines":[{"accountCode":"1100","direction":"DR","amount":25.00},
          {"accountCode":"2100","direction":"CR","amount":25.00}]}
```

Rules:

- At least 2 lines; amount > 0; total debits equal total credits, otherwise 409 `UNBALANCED_JOURNAL`.
- Unknown ledger account 404 `LEDGER_ACCOUNT_NOT_FOUND`; inactive 409 `LEDGER_ACCOUNT_INACTIVE`.
- Unknown period 404 `PERIOD_NOT_FOUND`; already closed 409 `PERIOD_CLOSED`.
- Idempotency: when an identical `(sourceType, sourceId)` already exists with the same content, return the original entry; different content 409 `JOURNAL_SOURCE_CONFLICT`.
- Reversal: generates `sourceType=REVERSAL, sourceId=<original entryId>` with swapped directions; the original entry is marked REVERSED; a repeated reversal returns the existing reversal entry.
- Trial balance: filters `posted_at` by period, aggregates each ledger account's DR/CR totals and net amount, and returns `totalDebit/totalCredit/balanced/items`.

## 4. Frontend

- Account view: shows product, total holds and available credit; supports creating/releasing holds.
- New page `#/postings` (business): type selection, account, amount, idempotency key, submit; recent batch list; reversal button.
- New page `#/ledger` (admin): chart of accounts, journal entry list, trial balance, close button; manual journal entry form (2 lines).
- Navigation and home page entries are updated in sync; the `web-ui` proxy gains posting/ledger paths.

## 5. Acceptance

1. `POST /posting-batches` succeeds: the account balance changes per INCREASE/DECREASE, and the batch and legs are persisted.
2. A repeated idempotency key returns the same batch; a different amount returns 409.
3. After a reversal the account balance is restored, the original batch is REVERSED, and the reversal batch directions are swapped.
4. The general ledger receives journal lines for the same batch; trial balance debits equal credits.
5. After period close, posting in that period returns `PERIOD_CLOSED`.
6. The frontend can complete: account hold → posting → view batch → reversal → view general ledger/trial balance.
7. All tests in the repository are green and Docker Compose starts (10 containers at A2, 11 after A1.4).
