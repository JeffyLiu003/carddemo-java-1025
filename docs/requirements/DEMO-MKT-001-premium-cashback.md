## 1. 背景与目标

### 1.1 业务背景

现网营销上下文已具备“白金卡 + 期限活动 + 消费返现”能力：活动按卡产品编码圈选客户，活动期内的达标消费按比例返现，返现通过账户贷记冲减欠款，奖励以 `(campaignId, transactionId)` 去重并保留 PENDING 重试（`docs/design/17-premium-cashback-campaign.md` §1、§3，ADR-013）。

本期业务诉求是在该能力之上，为白金卡客户提供一项**额外**返现：未来 3 个月内的消费，在白金卡既有返现之外再额外返 0.5%。原始需求同时声明：正式活动日期、消费范围、限额、退款规则尚未由业务确认（见文档信息“需求登记原文”）。

本文件的作用是把原始诉求转化为可开发、可测试的需求边界，并把业务口径缺口逐项显式登记，避免实现侧自行补成已确认规则。

## 3. 范围定义

### 3.1 In-Scope / Out-of-Scope

**In-Scope**

- 新增一项白金卡额外返现活动（3 个月、额外 0.5%），通过既有营销活动接口创建与配置。
- 活动生命周期：创建（DRAFT）、发布（ACTIVE）、暂停（PAUSED）、结束（ENDED）。
- 客户资格判定与活动可见查询（按账户号、卡号、客户号）。
- 报名（是否必需待确认；能力按可配置项实现）。
- 消费返现评估：活动期间、产品资格、报名状态、最低消费金额校验，按 `min(消费金额 × 0.005, 单笔上限, 客户剩余上限, 活动剩余预算)` 计算，2 位小数。
- 返现入账：账户贷记冲减欠款，失败保留 PENDING 并可重试。
- 客户返现记录查询、待入账记录重试。
- 退款与冲正回退处理（口径待确认；本期必须提供可执行的回退能力与去重保护）。
- 运营效果查看：报名数、奖励数、已发放数、返现总额、预算使用率、转化率。
- 审计留痕：活动创建/状态迁移、报名、返现评估、返现入账结果。

**Out-of-Scope**

- 积分、A/B 实验、复杂客群 DSL（ADR-013 决策 6）。
- 白金卡之外的其它卡产品编码活动。
- 返现提现、返现转出、返现兑换权益。
- 返现报表订阅与月度营销账单推送。
- 生产级统一鉴权网关与权限系统改造（ADR-007 遗留风险）。
- 历史活动数据迁移与旧营销模块恢复（ADR-013 后果第 4 条）。

#### REQ-CB-04 消费返现评估与计算（[REQ-CB-04]）

**功能描述**：交易入账成功后，transaction-service 调用 `POST /api/v1/reward-evaluations`。系统对每个 ACTIVE 活动依次校验：交易日期在活动期间、账户产品编码在适用列表、报名状态满足要求、消费金额 ≥ 最低消费金额；通过后计算返现：
`返现 = min(消费金额 × 0.005, 单笔上限, 客户剩余上限, 活动剩余预算)`，结果保留 2 位小数（HALF_UP）。
同一活动与同一交易只评估一次，重复评估返回 duplicates，不重复生成奖励。

**字段级需求表**：

| 字段 | 类型 | 必填 | 格式/校验 | 默认值 | 来源 |
|------|------|------|----------|--------|------|
| transactionId | string(16) | 是 | 非空，交易唯一键 | 无 | transaction-service |
| accountId | string(20) | 是 | 非空 | 无 | transaction-service |
| cardNumber | string(19) | 否 | 非空时作为返现记录展示字段 | 空 | transaction-service |
| customerId | string(20) | 是 | 非空 | 无 | transaction-service |
| amount | decimal(14,2) | 是 | > 0 | 无 | transaction-service |
| occurredAt | timestamp | 是 | ISO 时间；交易时点口径待确认（12.3-9） | 无 | transaction-service |
| cashbackAmount | decimal(14,2) | 是 | ≥ 0，2 位小数，HALF_UP；超出上限时取上限值 | 计算值 | RewardCalculator |
| grants | array | 是 | 命中的奖励数组 | 空数组 | marketing-service |
| skipped | array | 否 | 未命中活动与原因码 | 空数组 | marketing-service |

**异常矩阵**：

| 异常场景 | 系统行为 | 错误码 | 用户提示 |
|---------|---------|--------|---------|
| 交易金额 ≤ 0 | 拒绝评估 | `INVALID_AMOUNT`（400） | 内部错误，记录 WARN |
| 交易时间为空 | 拒绝评估 | `INVALID_OCCURRED_AT`（400） | 内部错误，记录 WARN |
| 交易号、账户号或客户号为空 | 拒绝评估 | `INVALID_TRANSACTION_ID` / `INVALID_ACCOUNT_ID` / `INVALID_CUSTOMER_ID`（400） | 内部错误，记录 WARN |
| 交易未命中活动期间 | 该活动进入 skipped，原因 `OUT_OF_WINDOW` | 无（按规则跳过） | 不展示 |
| 产品编码不匹配 | 该活动进入 skipped，原因 `PRODUCT_NOT_ELIGIBLE` | 无 | 不展示 |
| 未报名且活动要求报名 | 该活动进入 skipped，原因 `NOT_ENROLLED` | 无 | 不展示 |
| 消费金额低于最低消费金额 | 该活动进入 skipped，原因 `BELOW_MIN_AMOUNT` | 无 | 不展示 |
| 客户累计上限已满 | 返现为 0，记录 skipped 原因 `CUSTOMER_LIMIT_REACHED` | 无 | 不展示 |
| 活动预算已耗尽 | 返现为 0，记录 skipped 原因 `BUDGET_EXHAUSTED` | `CAMPAIGN_BUDGET_EXHAUSTED`（事件记录） | 不展示 |
| 同一交易重复评估 | 返回既有奖励并列入 duplicates | 无（去重命中） | 不展示 |
| 营销服务不可用 | 入账成功不回滚，仅记录 WARN | 无（异步补评估口径待确认，见 12.1） | 不展示 |

## 5. 业务规则

| 编号 | 规则 | 来源 | 优先级 | 验证点 |
|------|------|------|--------|--------|
| BR-CB-01 | 活动适用产品编码为 `PLATINUM`，非白金卡账户不参与评估 | 原始需求 C-01 + ADR-013 决策 4 | 必须 | 金卡账户 `00000000007` 评估返回 `PRODUCT_NOT_ELIGIBLE` |
| BR-CB-02 | 活动期限为 3 个月，`endDate = startDate + 3 月 - 1 天` | 原始需求 C-02 + 设计 17 号 PC-01 | 必须 | startDate 2026-11-01 时 endDate = 2027-01-31 |
| BR-CB-03 | 返现比例为 0.005（额外 0.5%） | 原始需求 C-03 | 必须 | 消费 1000.00 时比例部分为 5.00 |
| BR-CB-04 | 仅活动期间内、已入账的消费交易参与评估 | 设计 17 号 PC-03 + 待确认 12.3-9 | 必须 | 期间前一天与后一天的交易进入 skipped |
| BR-CB-05 | 返现 = min(消费金额 × 0.005, 单笔上限, 客户剩余上限, 活动剩余预算)，2 位小数 HALF_UP | 设计 17 号 PC-07（业务口径待 12.3-5） | 必须 | 消费 1000.00、单笔上限 5.00 时返现为 5.00；上限 3.00 时为 3.00 |
| BR-CB-06 | 同一活动与同一交易只返现一次 | 设计 17 号 PC-08 | 必须 | 同一 transactionId 连续评估 3 次，奖励记录为 1 条 |
| BR-CB-07 | 客户累计返现按 PENDING 与 GRANTED 合计计算上限；预算在创建 PENDING 时预占 | 设计 17 号 PC-09 | 必须 | 客户上限 10.00 时第 3 笔返现为 0 |
| BR-CB-08 | 返现通过账户贷记入账，`creditId` 去重，余额可为负 | ADR-013 决策 3 | 必须 | 同一 creditId 调用 2 次，账户余额只减 1 次返现额 |
| BR-CB-09 | 返现入账失败保留 PENDING 并可重试，成功后置 GRANTED | 设计 17 号 PC-10 | 必须 | 停用 account-service 后评估，状态 PENDING；恢复后重试置 GRANTED |
| BR-CB-10 | 营销评估失败不影响交易入账 | ADR-013 决策 2 | 必须 | 停用 marketing-service 后提交交易，交易入账成功 |
| BR-CB-11 | 活动状态迁移仅允许 DRAFT/PAUSED→ACTIVE、ACTIVE→PAUSED、ACTIVE/PAUSED→ENDED | 设计 17 号 §3.1 | 必须 | ENDED→ACTIVE 返回 `CAMPAIGN_INVALID_TRANSITION` |
| BR-CB-12 | 退款与冲正按业务确认口径追扣已发放返现，同一退款交易只处理 1 次 | 原始需求 C-08（口径待确认） | 必须 | 全额退款后追扣金额与确认口径一致；重复投递不重复追扣 |
| BR-CB-13 | 额外返现与既有白金卡返现活动的并存方式按业务确认口径执行，未确认前不得自行合并或覆盖 | 原始需求 C-03 + 待确认 12.3-6 | 必须 | 确认前同一交易只命中本期活动 1 条奖励 |
| BR-CB-14 | 活动前已发生消费默认不补发，若业务确认补发则按补发口径执行 | 待确认 12.3-8 | 应该 | 活动起始日前的交易不产生奖励（除非确认补发） |

| 性能 | 活动与资格查询 p95 < 800ms；报名与创建提交 p95 < 1200ms | 50 并发压测，采集 p95 |
| 性能 | 返现评估与账户贷记合计 ≤ 2 秒（同步调用路径） | 端点计时，超 2 秒记录 WARN |
| 可用性 | marketing-service 不可用时交易入账成功，返现延迟 | 停用 marketing-service 后提交交易并核对入账 |
| 一致性 | 账户余额变动与奖励状态最终一致；PENDING 可在 24 小时内重试成功 | 停用再恢复 account-service，核对状态与余额 |
| 去重 | 评估、贷记、追扣、报名四类写操作支持去重键 | 同一键重复请求 3 次，断言记录数为 1 |
| 预算保护 | 单实例内预算与客户上限不被突破 | 并发 50 笔评估，断言返现总额 ≤ 预算 |
| 审计 | 活动创建、状态迁移、报名、评估、入账、追扣全量留痕 | 查询审计事件序列，核对 6 类事件齐全 |
| 可观测性 | 关键路径输出 traceId 与 `campaignId`、`transactionId`、`rewardId` | 检索日志与指标 |
| 告警 | 评估失败率、入账失败率、预算使用率 90% 阈值触发告警 | 检查告警规则并模拟触发 |

### 6.2 安全需求

| 维度 | 要求 | 验证方法 |
|------|------|---------|
| 认证 | 演示环境沿用 IAM 登录；生产化前由网关统一校验 token（ADR-007） | 无 token 调用活动接口，记录当前实际行为 |

## 9. 场景矩阵

| 类型 | 场景 | 角色 | 数据/接口 | 预期 |
|------|------|------|-----------|------|
| 主流程 | 创建并发布额外返现活动 | 营销运营 | POST `/campaigns` → `/activate` | 状态由 DRAFT 到 ACTIVE，客户可见 |
| 主流程 | 白金卡客户报名后消费 1000.00 | 持卡人 | POST `/enrollments` → 交易入账 → 评估 | 奖励 5.00，状态 GRANTED，账户欠款减 5.00 |
| 主流程 | 客户查询返现记录 | 持卡人 | GET `/rewards?accountId=` | 返回 1 条 GRANTED 记录，金额 5.00 |
| 主流程 | 运营查看活动效果 | 营销运营 | GET `/campaigns/{id}/performance` | 报名 1、奖励 1、已发放 1、返现总额 5.00 |
| 边界 | 消费金额使返现恰好触及单笔上限 | 持卡人 | 消费金额 = 单笔上限 ÷ 0.005 | 返现 = 单笔上限，2 位小数 |
| 边界 | 返现比例为 0.5% 后舍入到分位 | 持卡人 | 消费 999.99 | 999.99 × 0.005 = 4.99995，HALF_UP 后返现 5.00 |
| 边界 | 客户累计返现恰好达到客户上限 | 持卡人 | 连续 2 笔评估使累计 = 客户上限 | 第 2 笔返现使累计 = 上限，第 3 笔返现为 0 |
| 边界 | 活动最后一天 23:59:59 的交易 | 持卡人 | 交易时间在 `endDate` 当日 | 命中活动，产生奖励 |
| 边界 | 活动结束次日 00:00:00 的交易 | 持卡人 | 交易时间在 `endDate + 1 天` | 进入 skipped，原因 `OUT_OF_WINDOW` |
| 异常 | 同一交易重复入账 | 系统 | 同一 transactionId 评估 3 次 | 奖励记录 1 条，返回 duplicates |
| 异常 | 账户贷记失败 | 系统 | 停用 account-service 后评估 | 奖励 PENDING，恢复后重试置 GRANTED，余额只减 1 次 |
| 异常 | 营销服务不可用 | 系统 | 停用 marketing-service 后提交交易 | 交易入账成功，返现延迟，记录 WARN |
| 异常 | 活动预算耗尽 | 系统 | 连续评估使 consumed_budget = budget | 后续评估返现为 0，记录 `BUDGET_EXHAUSTED` |
| 异常 | 全额退款已返现交易 | 系统 | 退款交易入账 → 追扣 | 追扣金额按确认口径执行，同一退款只处理 1 次 |
| 权限 | 金卡客户查询本期活动 | 持卡人 | GET `/eligibilities?accountId=` | 返回 `eligible=false`，原因 `PRODUCT_NOT_ELIGIBLE` |
| 权限 | 客户调用创建活动接口 | 持卡人 | POST `/campaigns` | 403 或网关拒绝（权限矩阵待确认） |
| 权限 | 客户查询他人返现记录 | 持卡人 | GET `/rewards?accountId=他人账户` | 空列表，无数据泄露 |

| US-016 | [REQ-CB-07] | 已返现交易发生全额退款，追扣口径已确认 | 退款交易入账 | 追扣金额与确认口径一致，状态 DONE，账户余额变动可核对 | 构造退款交易 1 笔 |
| US-017 | [REQ-CB-07] | US-016 退款交易重复投递 2 次 | 再次投递同一退款交易 | 追扣只执行 1 次，账户余额只变动 1 次 | 复用 US-016 交易号 |
| US-018 | [REQ-CB-08] | 活动已有 1 报名与 1 已发放奖励 | 运营查看活动效果 | 报名 1、奖励 1、已发放 1、返现总额 5.00、预算使用率为返现总额 ÷ 预算 | 复用 US-006 数据 |
| US-019 | [REQ-CB-01] | 活动状态为 ENDED | 运营尝试发布活动 | 返回 409 `CAMPAIGN_INVALID_TRANSITION`，状态不变 | 结束 US-001 活动后重试 |

## 11. 依赖与约束

### 11.1 依赖

| 依赖对象 | 用途 | 失败影响与处理 |
|---------|------|---------------|
| marketing-service | 活动、报名、奖励、效果 | 评估与查询不可用；交易入账不受影响，奖励延迟 |
| account-service | 账户产品编码、贷记入账、追扣 | 资格判定失败或入账 PENDING；恢复后重试 |
| transaction-service | 入账后触发评估、退款与冲正事件 | 评估不触发；按补偿任务补评估（机制待确认） |
| web-ui | 客户与运营页面、接口代理 | 页面不可用；接口不受影响 |
| IAM | 登录与角色 | 无法登录；演示环境无接口级强制鉴权（ADR-007） |
| audit-service | 审计事件 | 写失败进入本地补偿日志 |
| notification-service | 活动上线与返现通知（是否发送待确认） | 主流程不回滚，记录待补发 |

### 11.2 影响分析

| 维度 | 影响 |
|------|------|
| 前台 | 营销入口活动卡片、我的返现页签、活动管理表单、活动效果页、首页角标 |
| 后台 | marketing-service 新增退款追扣接口与追扣表；activity 配置复用既有能力；account-service 复用贷记接口 |
| 数据 | 新增 `reward_reversal` 表；复用 `campaign`、`enrollment`、`reward_grant`、`account_credit` |
| 接口 | 复用 15 个既有接口；新增 1 个追扣接口 |
| 配置 | 活动参数（费率 0.005、期限 3、上限、预算、报名要求）、`MARKETING_ENABLED` 开关、告警阈值 |
| 测试 | 资格判定、返现计算与上限、去重、入账失败重试、退款追扣、权限边界 |
| 文档 | 本需求、营销活动操作说明、API 目录、权限矩阵、运行手册 |

### 11.3 约束

- 复用既有 marketing-service 与 account-service 贷记能力，不新建营销服务（ADR-013）。
- 活动预算与客户上限为单实例保护；多实例部署前必须补行锁或条件更新。
- 金额统一 `BigDecimal` 与 `numeric(14,2)`；费率 `numeric(8,6)`。
- 所有写接口支持业务唯一键去重；评估、贷记、追扣不可重复生效。
- 演示环境沿用 IAM 角色 `U` 与 `A`，不做接口级强制鉴权（ADR-007），生产化前必须补网关。
- 活动日期按服务器时区计算；生产上线前统一业务时区（待确认 12.3-9）。
- 本期不恢复旧营销模块，不引入积分、A/B、复杂客群能力。

## 12. 风险与假设

### 12.1 风险与应对

| 风险/假设 | 影响 | 应对 |
|-----------|------|------|
| 活动日期、消费范围、限额、退款口径未确认 | 实现按错误口径上线，返现多发或少发，返工成本高 | 未确认项保持待确认，参数全部配置化；本文件 12.3 逐项登记责任方，确认后再进入开发 |
| “额外 0.5%”与既有白金卡活动并存方式未确认 | 同一交易会重复返现或比例被覆盖 | 确认前同一交易只命中本期活动 1 条奖励（BR-CB-13）；确认后调整活动配置 |
| 预算与客户上限为单实例保护 | 多实例并发超发返现 | 单实例演示；生产前补行锁或数据库条件更新，并加并发验收用例 |
| 报名接口未二次校验卡号与账户归属 | 他人卡号可被填入报名记录 | 报名时由 account-service 校验卡与账户归属；确认前记录为已知限制 |
| 交易后置评估为同步调用，最坏增加 2 秒 | 收单体验下降 | 监控 p95；超阈值告警；评估失败不回滚入账 |
| 退款追扣涉及已发放资金 | 客户投诉与账务差异 | 追扣全部留痕并可查询；失败转人工工单；上线前账务口径会签 |
| 演示环境无接口级鉴权（ADR-007） | 未授权访问风险 | 仅本地或内网暴露端口；生产化前实施网关方案 C |
| 活动指标值与目标版本未确认 | 目标无法验收 | 上线前补充 1.2 表的目标值 |

### 12.2 假设

- 本期只上线 1 个白金卡额外返现活动，活动编码由运营在确认后指定。
- 返现形式为冲减信用卡欠款，不涉及现金转账与提现。
- 报名是否必需由运营配置决定，系统能力两种配置均支持。
- 既有 `PLATINUM_3M_CASHBACK` 活动在活动期间结束后自然失效，本期活动是否替换该活动取决于 12.3-6。
- 客户查询与运营查看沿用既有“营销”菜单与页面结构。
